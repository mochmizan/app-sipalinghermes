# admin — AGENTS.md

## Purpose

- Admin control plane at `/admin/`: platform health, waiting-list leads, Repliz key UI, users & agents, runtime, capabilities, queues/dead-letter, audit, LLM, settings (contract facts only)

## Ownership

- Owns `admin/index.html` only; the page's live behaviour lives in the `// --- Hermes agent runtime (admin) ---` block of root `app.js` (root-owned — changes there are edits to a shared file, not to this folder)
- Guarded by `body[data-required-role="admin"]` check in root `app.js`; non-admin gets redirected to `/auth/?mode=login`

## Local Contracts

- Waiting-list table (`#admin-wl-table-body`, `#admin-wl-badge`, `#btn-admin-export-wl`) reads `GET /api/admin/waitinglist` with `Authorization: Bearer <token>`; caller must be `role=admin` or API returns 403
- Repliz key form (`#input-repliz-key`, `#input-repliz-workspace`, `#btn-save-repliz`, `#btn-clear-repliz`, `#btn-toggle-repliz-vis`) stores credentials in `localStorage` keys `hermes_repliz_api_key` / `hermes_repliz_workspace` only — never send them to the backend (no such endpoint exists)
- Live runtime panels (contract: root `agent-runtime.design.md`), all Bearer-gated and `role=admin`: users & agents table `GET /api/admin/agents` (LEFT JOIN + real status, per-row `POST /api/admin/agent-action` `enable`/`disable`/`run_report`), queues `GET /api/admin/agent-jobs` (last 50, dead-letter notes from `error`), audit `GET /api/admin/agent-audit` (last 50, actor/action/target/time), LLM panel from the agents payload (`provider_host`, `model`, `configured` — never the key)
- Runtime/health panels derive from those responses (status distribution, queue depth, LLM configured); zero fake numbers or fabricated audit IDs — empty responses render honest empty states, and requeue of failed jobs is the only write from the queue panel
- IDs consumed by root `app.js` (`admin-wl-table-body`, `repliz-*`, `btn-admin-export-wl`) must not be renamed without updating `app.js`
- Live-region IDs consumed by the `// --- Hermes agent runtime (admin) ---` block in root `app.js` (guarded by `#runtime`, section anchors `#users`/`#runtime`/`#queues`/`#audit`/`#llm`/`#capabilities`/`#settings`): `admin-agents-body` + `admin-agents-tag` + `admin-agents-refresh` + `admin-agents-badge`, `admin-jobs-body` + `admin-queues-tag` + `admin-queues-badge`, `admin-audit-body` + `admin-audit-refresh`, `admin-runtime-list`, `admin-capabilities-list`, `admin-llm-list`, `admin-metric-agents(-trend)`, `admin-metric-queue(-trend)`, `admin-health-note` / `admin-health-tag` / `admin-health-refresh`, `admin-system-state`. Renaming one without updating `app.js` blanks that panel. Row markup is generated by `app.js`; `data-admin-action` (`enable`/`disable`/`run_report`/`requeue_failed`) values are the only action hooks
- Admin region analytics: exactly one new PostHog event `agent_admin_action {action}` (guarded `track()`, fired on success only). Never emit user ids, agent ids, emails, handles, `status_detail`, job `error`, or audit `detail` text — panel rows may show them, events may not
- The admin region refreshes all three endpoints every 20s while the tab is visible, toasts real API results/messages, confirms before disable/requeue, and on 401 renders the honest `Sesi berakhir` state in every panel instead of redirecting (admin endpoints answer 403 `Hanya admin yang memiliki izin akses.` for a dead session; that message is rendered as-is)
- System Settings panel is static copy that must stay limited to contract facts (5s tick + 5 min reaper, 3-attempt dead-letter + admin requeue, one `scheduled_report` per ISO week `%G-W%V` with `INSERT OR IGNORE`, 20 chat/min/user with 2 in-flight, 90s LLM timeout, no automatic retention delete). Add a card only when `agent-runtime.mjs` really implements the claim
